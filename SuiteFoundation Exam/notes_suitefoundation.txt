    Revisão de items:{
        List > acc > itens

        inventoryItem: {
            itens de estoque, na aba de compras e inventário, podemos colocar os dados e valor de compra, descirção de compra etc...
            podemos colocar fornecedor na aba de purchase. 
            Accounting, é onde setamos as contas do item e até o tax schedule. 

            set up a inventory item. que pode ser lote numerado ou serializado. 
            dá para setar o costing method e o valor de compra e colocar o valor de venda também nas subtabs designadas.

            SÓ DA PARA USAR O MATRIX DOS ITEMS SE O ADVANCED INVENTORY MANAGEMENT
            esse carinha aí, dá para criar um item pai e dentro do assistente é possível colocar mais derivações, como tamanho, cor etc... Definido pelo usuário.
            primeiro seta o item pai, depois cria as listas para fazer a matriz. (não pode ter abreviações iguais) 
            
            Após setar os atributos designados no passo de propriedades, é possível fazer as possíveis combinações cruzandos as listas de atrubitos que criamos. 
            e no ultimo passo, é onde poderá ser eliminado as combinações que não temos (exmeplo se temos uma lista de tamanhos com 5 tamanhos e uma de cores com 5 cores
            na combinação estarão os 25 itens, porém é nesse passo que podemos definir qual não teremos, assim diminuindo o valor em questão)

            ele mostrará quantos foram criados de quantos considerados

            NA CRIAÇÃO DE ITENS POR MATRIZ, TEM UM QUANTIDADE LIMITE A CONSIDERAR 2000 itens o limite.

            Após isso, eles ficaram aninhados no item pai e para fazer a atualização do preço de todos em conjunto entre no item pai e na aba de vendas coloque o preço
            na sublista. O mesmo é valido para as contas, E PARA APLICAR NA MATRIZ COMPLETA, NO BOTÃO ACTIONS TERÁ O "UPDATE MATRIX"
        }

        noninventoryitens: {
            tem 3 tipos, purchase, sale, resale
            purchase: {
                algo que você compre para utilizar em área;
                dá para colocar a expense account    
            }
            resale{
                algo que você compre para revender (estoque em Supermarkt)
                é bem parecido com o purchase, só muda a conta, income account

            } 
            sale:{
                produtos que a companhia fabrica ou vende sem precisar de entrada.
                income account.
            } 

            É O ÚNICO TIPO DE ITEM QUE PODE SER CONVERTIDO EM ITEM DE ESTOQUE, E ISSO AJUDA QUE NÃO É PERDIDO O HISTÓRICO DE VENDAS E COMPRAS DELE APÓS A MUDANÇA.
            dá para converter para serializado, lote numerado e para item de estoque padrão.
        }

        Service Item: {
            Geralmente usado em projetos, com projetos avançados, assim é possível fazer a parametrização para sempre que o item for vendido será criado um
            um projeto para aquela venda, Serviços de venda e revenda. (tem as 3 frentes de subitpos)

            se a feature estiver habilitada, é possível colocar despesas no pedido de compra, se não só será possível colocar item, só temos a conta de despesas.
            preferencias, podemos setar de ele é "entregável ou recebível" e isso vale para todos os subtipos.

            Itens de serviço podem ser usados como rastrteio de tempo em horas faturáveis (assim como a ACS usa), intercompany time feature
        }

        AssemblyItens, item group, Kit/Package: {
            assembly: {
                pode ser lote numerado ou serializado, não temos o valor de compra por conta que lá em componentes conseguimos colocar o item que vamos usar
                e podemos colocar quantidade, assim o item que foi criado como noninventory ou inventory itens são selecionados e assim puxam o valor da parametrização deles

                Assim é possível colocar mais de um item para o assembly, service, other charges e othergroups (nas bases que temos, não localizei os componentes)

                Na aba vendas e precificação é possível colocar o preço do item em si, 

                Na aba contabilidade temos as contas, asset acc, cogs acc, income acc e dá para setar o tax schedule

                caminho para criar assemblies> Transaction > Manufacturing > Build Assemblies
                nesse registro, selecione o assmbly item que deseja aplicar, selecione a localidade, e a quantidade de itens que serão criados
                e os componentes serão atualizados com a quantidade que será necessária para criar o assmebly Item, é possivel setar os componentes individualmente.
                criando pelo build, o estoque será atualizado com as quantidades dos componentes atualizados.
            }
            item group: {
                é para criar um item que carregue outros itens, ele tem os componentes tem o flag de display components on transaction. Assim é possível 
                carregar os componentes desse "pacote" na transação. (é bem parecido com o Assembly), ele não tem nenhum tab de parametrizção por conta que
                cada componente já tem o seu individual.
            }
            Kit/package: {
                temos também os componentes na aba de inventário e compra, no sales pricing da para colocar o base price para o kit,
                e na acc tab só temos a income account. Não são itens que são mantidos em stock, eles precisam ser compilados conforme
                eles são cumpridos, o motivo de ser um kit package sempre reportarão 100% de lucro.
            }

            ao colocar na transação, o único que mostra os componentes são os group, ambos os outros mostram só o valor que foi definido no pricing dentro dos itens.
            o assembly e package só aparecem caso seja impresso (template da transação como advanced html) que irá mostrar todos os itens nele contidos. 
        }

    Sales Pricing Subtab:{
        no item de estoque na subtab de sales pricing conseguimos setar os valores em mult currency,  
        se estiver utilizando o ecommerce, o valor que irá será o online price,

        base price always in the top, online price always in the botton
    }
    Enable pricing features: {
        enable features, transactions e sales tab
        muitple prices: mantem multiplos preços por item, podendo setar um item padrão para cada cliente
        quantity princing: dá para dar desconto de acordo com a quantidade de itens a vender;

        Accounting preferences: item/accounting {
            sales princing tab: Tem o campo de máximo de quatidade com preço base definido, o máximo é 50
            liberar o disconto por quantidade;
            incluir reembolso na venda forecast reports;
            incluir a entrega no forecast reports;
        }
    }

    using pricing feature:{
        setup prince levels;
        define quantity price levels.
        create pricing groups

        setup > acoounting > accounting list.
        filter in price level. (são aqueles preços que ficam na aba de sales dos itens, é aqui que cria outros ou altera algum)

        aqui é possível setar o nome o desconto aplicado (desconto tem que ser negativo e markup é positivo)
        MARKUP: um valor que representa a diferença do valor da venda com o custo do produto ou serviço. 
        
        tem uma flag de update existing prices que ao ser aplicada o valor do base price dos itens serão aplicados com a taxa de markup ou
        desconto. EX se o base price for 100 e coloquei um com nome "desconto" com -10% o valor do desconto firará 90 e para o markup só 
        aumentará o valor da porcentagem.

        quantity pricing schedules: {
            são templates que podemos aplicar em um item que gerará automaticamente preços de compra e venda baseados na quantidade.
            list > account > quantity pricing levels
            dento desse registro podemos passar o nome, na sublista colocamos quantidade e o desconto (Sempre negativo)
            campo de calcular a quantidade de desconto, temos algumas seleções para este campo:
                por linha: que se aplica na quantidade da linha
                por quantidade no geral: que se aplica para todas as linhas da transação
                parent quantity: verifica os itens de matriz e ignora as opções de tam e cor (no exemplo dos atributos que temos)
                overall schedule: parece ser o memso que coloquei na quantidade em geral (ele aplica o valor do desconto de 
                acordo com a quantidade dos itens na transação QUE PERTENCEM AO MESMO PRICING SCHEDULE)
            
            o bloco abaixo é dentro do item
            é aplicado no campo quantity pricing schedule e ele aplicará dinamicamente os valores do desconto e a quantidade no registro.
            use marginal rates: parece que o valor será aplicado pela qantidade até que atinja outro nível de desconto (não entendi)
            calculate quantity discounts, o campo do tipo de quantidade (o mesmo do pricing schedule) 
        }

        pricing group: {
            setup > accounting > accounting list: 
            filtro pricing group
            só tem o nome do princing group
            se for colocar todos os itens da matriz criada (exemplo) basta só alterar o parent
            lembrando que ao mexer no pai, precisa fazer o update matrix.

            Ele pode ser atribuído ao cliente e assim se ele comprar (sales order) um item desse grupo, ele receberá um desconto especifico.
        }

        item record e vamos setar o pricing: {
            inventory Item:{
                sales/princing tab, temos os campos de quantity princing, calculate quantity discount e princing group
                caso set o princing schedule, serão setados os preços dinamicamente.
            }
            lembrando que esses 3 campos mencionados é como é feito a parametrização dos dados no item, assim pode fazer outros itens com os mesmos dados e assim
            sucessivamente. 
        }

        princing in a customer record: {
            customer rec > financial tab
            podemos setar o princing level, no final do registro, podemos setar o group pricing para o cliente, exemplo as camisetas group de aparencia, e passar o price level
            assim podemos definir se para tal price level terá desconto ou não.

            na próxima tab de item pricing: podemos colocar preço para itens especificos para esse cliente. 
            a sequencia que o NS olha para o princing do cliente é: Item pricing  (se não tiver dados) > group pricing (se o item que ele tá comprando pertence a algum grupo ele vai setar 
            o price level que está na linha) > price level do corpo (o que será levado em consideração se o cliente não tiver os dados o bottonpage preenchidos) e se deixar em branco
            ele recebera por default o "base price" 
        }

        Dá para alterar na própria transação mesmo após o set automático. NÃO PODE OCULTAR O AMOUNT DA LINHA SE NÃO PODE DAR PROBLEMA DE CALCULOS já o pricing entre outros podem ser
        ocultos.

        Atulaização em massa:{
            listas : atualização em massa > mass update
            listas : atualização em massa > update prices
            itens: update item price, é possível setar os dados de acordo com com o price levels, passa o valor no amount ( se colocar % será a porcentagem, se não será o valor add)
            based on é onde indicará o valor que será alterado, um existentem, custo recente, média entre outros tem um campo de arredondamento, que pode ser usado de acordo com o param
            passado lembrando que é apenas os valores uqe serão alterados. 
        }

6th Vídeo: Order Management: {
    este módulo trata de administrar inventários (warehouses) e Entrega de pedidos com controle de tempo.
    
    explora as considerações de habilitar o gerenciamento de order e as tarefas de configurar o order management
    e o passo a passo de atendimento do pedido de vendas.

    basicamente vamos ver o fluxo de criação do (customer) pedido de venda, desde a (prospect) cotação, aprovação, cumprimento do pedido, criação da fatura e aceitar o pagamento.

    a warehouse trabalha com todos o pedidos que estão com o status de pending fullfilment status, após eles aplicarem todos os itens do pedido ele é atualizado para
    pending billing é possível que eles seja parcialmente atendido então ele ficará com parcialmente atendido de pendente do faturamento.

    SO são trnasaçoes que podem vender Bens ou serviços
    não tem impacto até o item for entregue ou o serviço completo

    no GL impact dá para ver se foi postado
    
    pode ser gerado por um recebmento de de pedido de compra;
    uma compra online;
    uma venda online que foi gerada a partir da central do cliente; (onde os distribuidores ou revendores podem criar os pedidos deles)
    
    podemos selecionar os formulários para o pedido de venda, entre eles: standart == sales order, salesorder cash sale, invoice, progress billing
    pode ser customizar cada um. 

    se não passar o terms, and paymenthod, se não selecionar nada nesses campos o sistema vai entender que é uma invoice e gerar uma invoice.

    no enable features vamos em transações na basic features aí podemos habilitar ou desabilitar diferentes transaçãoes no sistema
    o advanced shipping caso não setado, assim que o pedido for atendido será criada fatura dele, se não alguém o account receivable dpto vai fazer
    a geração da invoice. 

    acc preferences order management tab
    dá pra colocar o status padrão do pedido de venda
    dá para habilitar o disparo de email automático quando o pedido for cancelado
    dá para setar um armazem padrão de onde sairam os itens


    order to invoice Process:{
        crinado uma SO do zero, após a criação dele o pedido ficou como pendente de aprovação, então se tiver a role que faça essa aprovação basta ir 
        em vendas > aprovação de pedidos de vendas, dá para aprovar em massa ou indo no registro e apertar o botão, após isso o status será atualizado
        para pendente de atendimento e tem o botão de atender. 

        criando o atendimento: pode colocar a quantidade de atendimento e tem que aplicar o setar no flag, após a criação do registro ele ficará com status
        de picked e após isso pode clicar em packed a após isso pode colocar como shipped SEPARADO, EMPACOTADO E ENVIADO. Após o shipped é liberado o botão
        bill da atendimento do item, e o status do pedido fica como pendente de fatura. 
        temos 2 opções, próxima fatura ou faurar remanescentes, após criar a bill, na bill, o campos created from fica com a SO e no ralated record fica em branco
        e no pedido ficam amarradas as bills e os atendimentos dos itens. 

        é possível fazer a impressão da fatura no botão da impressora, e para setar os forms de impressão é em transações > gerenciamento > imprimir cheques e forms
        clicando na invoice você consegue setar a location, o form, temos o campo que nos indica os documentos na fila, e o botão de perimitir reimpressão. 
        irão se preenchidas as linhas da sublista e pode imprimir mais de uma simultaneamente.  

        se o multlocation estiver ativo, a localização fica obrigatória.

        Dica: se precisar alterar o formulário, salve primeiro as alterações e depois altere formulário

        caso crie uma SO que tenha um item de drop shipping, é criado um pedido de compra com este item (isso até para uma SO Que tenha 2 itens, vai criar uma PO
        para cada item separadamente), assim quando o fornecedor enviar o item (drop shipping {por isso a PO}) é possível marcar o item como shipped
        no item de drop ship temos a flag que indica que é dropshipping, se quiser que crie o pedido de compra automáticamente, precisa setar o flag do drop shipping
        e colocar o fornecedor no item e marcar como preferencial 

        e para itens de special ordem tem o flag de special order item e tem a tab do fornecedor também, para criar auto a PO precisa desses dados preenchidos.
    }
